## Правила продвижения — обязательно для всех следующих чатов

1. **Никогда не создавать новый план вместо этого файла.** Единственный порядок — M00 → M17. Прежде чем ответить «П», прочитать живую `main:ROADMAP_RU.md`, а не полагаться на устаревший handoff, память или написанный ранее процент.
2. **Начинать с первого незакрытого подэтапа M04.1** (после завершения — M04.2 и т. д.). Если работа не укладывается в один подход, коммитить малую атомарную часть и оставлять тот же 🟡 подпункт.
3. **Не переходить к следующей стадии только потому, что закончилась компиляция**: `Core Parity` ≠ `NeoForge compile` ≠ `реальный Minecraft`. В таблице указывать точные хэши коммитов и ссылки на фактические CI.
4. **Каждый завершённый кусок**: внедрить исходную механику BETA26 (без заглушек/фальшивых ресурсов) → сделать тест → commit в `main` → проверить CI → обновить подэтап/доказательства **в этом же файле**. Ни один новый чат не «сбрасывает» прогресс.
5. Когда M04 полностью закрыт, **одним коммитом** пометить M04 🟢, M05 🟡; далее аналогично по очереди. **В каждый момент ровно один 🟡 верхнего уровня**.
6. Исправление найденного при текущем этапе блокера разрешено. Перестановка этапов/смена цели — **только по прямому решению пользователя**, после которого обновить карту и указать причину.
7. Для приёмки широких этапов проверять survival, оригинальные рецепты/лут, данные world/NBT, безопасный перенос реальных ресурсов, визуал и multiplayer по применимости. Нельзя «закрыть» механику только моками или количеством Java-классов.
8. **Оценка 59/100** живёт отдельно от статусов этапов. Пересчитывать только по постоянной матрице `analysis/PROGRESS_AUDIT_2026_10_16.md` с обоснованием и доказательством; не выводить «процент дорожной карты» как «процент переноса».
9. Перед завершением подхода проверить `main` HEAD, записать в handoff последние сделанные коммиты, номер рабочего этапа, следующую атомарную задачу и статусы CI. В новых чатах handoff — справочник, **ROADMAP — главный источник выбора задачи**.
10. Для длительных Minecraft-тестов разрешены параллельные небольшие правки **в рамках текущего этапа**. Не проводить пассивное ожидание вместо продвижения. Сетевые сбои не приравнивать к провалу Java без лога.
11. Начальный запрос нового чата: **«Продолжай порт по `ROADMAP_RU.md` из `craftkot/tgaumcraft`. Fresh-read `main`, найди 🟡 M04 и выполни следующий подпункт. Ничего не начинай заново, обнови карту и сделай commit».**
