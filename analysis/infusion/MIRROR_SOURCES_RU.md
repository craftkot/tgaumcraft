05.11.2026. Перенос отдельного беспроводного пути `IAspectSource`; существующая трубная логика M04 не изменяется.

## Первичный источник

Официальный `Thaumcraft-1.12.2-6.1.BETA26.jar`, SHA256 `9425f8643581b27ff8845b087c8bc6fc10425a32942f1a3f0e265ce6b38f7b5f`. Изучены `TileMirrorEssentia.takeFromContainer`, `addInstability` и `EssentiaHandler.drainEssentia/getSources` через Java21 javap. JAR и полные дизассемблированные классы в Git не добавляются.

| Подтверждённое правило | Перенос |
|---|---|
| Матрица вызывает drain с null-facing и range12 | Существующий matrix entrypoint сохранён; один источник может быть реальным зеркалом |
| Mirror.takeFromContainer вызывает drain у связанного партнёра: facing партнёра, range8, ignoreMirror=true, delay5 | Новый узкий `EssentiaMirrorBlockEntity.takeForInfusion`, общий scanner в режиме без зеркал |
| Поперечные координаты от −range до +range включительно; глубина от0 до range−1 | `LegacyInfusionSourceVolume`; все6 направлений, null делегирует прежнему matrix-volume |
| Источники сортируются по квадрату расстояния; равные сохраняют порядок обхода | Стабильная сортировка, фиксированные golden-тесты порядка |
| Заблокированный IAspectSource не участвует; зеркало не хранит запас | Физическая банка проверяется перед списанием и после; ни буфер, ни выдуманная эссенция не создаются |
| После полного неуспешного поиска cache сбрасывается, повторный scan через10000ms | Сохранён прежний wall-clock backoff; runtime-кэш не сохраняется в NBT |
| После успешного takeFromContainer вызывается addInstability(null,amount) | Загрязнение накапливает только вызывающее зеркало; partner не получает второй начисленной единицы |

В `takeFromContainer` исходник отвергает amount>1; внешний matrix drainer всегда просит1. Порт дополнительно отвергает невалидные amount≤0. Проверка связывания использует существующую строгую reciprocal-модель и не загружает отсутствующие чанки. Это явно сохранённая защита порта, а не утверждение об отсутствии chunk load в оригинале.

## Архитектурная граница

У каждой матрицы свой scanner; у каждого зеркала отдельный scanner для запросов со стороны его партнёра. Ключ cache включает объект ServerLevel, позицию, дальность, направление и запрет зеркал. Объекты из cache повторно получаются из живого мира: сломанный/заменённый источник или нарушенная связь не разрешают списание. Обе стороны не могут рекурсивно вызвать другую пару.

В общий M04-класс добавлены только отдельное поле/scanner, wireless-метод и сброс этого cache при NBT load. Существующие методы `takeTransport`, `pullOneToRemoteJar`, suction и рецепты зеркал не переписаны. Координатору требуется учитывать этот небольшой конфликт при интеграции feature/alchemy.

Поддержаны реально существующие банки и зеркала. Остальные оригинальные реализации IAspectSource требуют собственных адаптеров, а исходные FX-пакеты пока не перенесены. Сохраняется известная неатомарность jar/matrix/pedestal при аварийном hard-kill. Между измерениями используется настоящий ServerLevel партнёра; равные координаты не объединяют источники.

## Проверка

Автоматические сценарии проверяют шесть направлений, заблокированные/чужие/задние/слишком дальние банки, приоритет местного источника, разрушенную пару, отсутствие рекурсии и force-load, смену направления cache, межмерное списание, оплаченный ритуал и восстановление NBT. Отдельный cold WRITE→READ запускает две серверные JVM с банками в другом чанке. Точные фактические результаты и команды записываются в [evidence](../evidence/infusion/mirrors_2026_11_05/README.md), а не выводятся из наличия тестовых методов.
