BETA26 SealHarvest использует IPlantable для семени/почвы и отдельную ветвь BlockDirectional; onItemUse вызывается на настоящем item, plantingXP начисляется после SUCCESS, стоимость — одно семя. В NeoForge1.21.1 IPlantable удалён. Public `registerSeed(crop, actualSeed, expectedPlant)` явно задаёт результат вместо догадки по наследованию BlockItem. Двухаргументный API сохраняет прежние правила/ошибку при неизвестном non-BlockItem. Completion/NBT требуют authoritative mapping, exactseedcomponents и expectedblock. Сохранённый формат не расширялся, старые vanilla rows продолжают читаться.

Callback выполняет настоящий ItemStack.useOn с actual reserved seed. Vanilla/NeoForge проверяют survival/protection и списывают реальный предмет; если callback оставил резерв, Harvest оплачивает один предмет сам, как source. Это верно и при изменении компонентов callback. Остатки возвращаются existing recovery; копия семени не используется как платёж.

Исследован реальный CommonHooks.onPlaceItemIntoWorld NeoForge21.1.250: нет finally вокруг Item.useOn, а перед placement event snapshots переносятся в local list. Farm теперь отказывается от вложенного чужого capture, при RuntimeException восстанавливает свои captured blocks/целевую ячейку/флаги, возвращает только действительные оставшиеся items. Mutation followed by PASS не оставляет неоплаченное растение без protection event. Это ограниченное восстановление данного вызова, не транзакция любых внешних item/entity/container side effects и не исправление crash atomicity.
