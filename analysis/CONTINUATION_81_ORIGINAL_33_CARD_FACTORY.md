## Original audit

Disassembled the user-provided original BETA26 JAR with `javap -c -p` for `ResearchTableData.drawCards`, `generateCard`, `ContainerResearchTable.enchantItem`, and the `initialize()` methods of all registered classes.

- Exactly **33** original TheorycraftManager registered card classes. **19** have no subclass NBT fields; **14** write additional specific fields. Of the 19 fieldless, exactly **14** inherit `TheorycraftCard.initialize` (always true) and **five** have gates: Balance (nonblocked totals), Ponder (blocked count), Rethink (sum >=10), Spellbinding (player XP level >0), Synergy (ARTIFICE+ALCHEMY+INFUSION >=15). CardEnchantment inherits TRUE even without XP for activation; do NOT conflate draw-time with activation-time XP checks.
- **Exact original draw RNG:** each attempted registered class consumes one player `Random.nextLong()` BEFORE calling initialize. The aid branch uses one `nextFloat` and `nextInt(aidCards.size)`; normal branch uses the Java HashMap key-array order `nextInt(33)`. Rejected candidates still burn their card seed. Original normal branch catches exceptions and retries. The 25% aid chance and 10,000 maximum attempts are preserved in the existing pure `LegacyTheorycraftDrawEngine`.
- **Exact original draw cost:** ContainerResearchTable buttons 2/3 consume **one paper only** in the table paper slot. Card activation buttons 4..6 consume ink after successful activation, not at draw. The new server method never charges ink on draw.
- Original `generateCard` may return an uninitialized card after an exception due to catch-and-return; **ported fail-closed behavior** rejects incomplete/unsafe original card state instead of creating a fake card.
