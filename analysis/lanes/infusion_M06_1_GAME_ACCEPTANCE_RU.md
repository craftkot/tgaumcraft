# M06.1 — критерии приёмки настоящей оплаченной инфузии

**Ветка:** `feature/infusion`, BETA26 → Minecraft 1.21.1 NeoForge. **Статус: НЕ ПРОЙДЕНО** — до конца 10-го подхода доказаны Core regression + full Java/JAR/dedicated-server startup, но нет end-to-end Survival и cold-restart. Этот документ — строгая спецификация проверки, **не отчёт об уже успешном Minecraft-тесте**.

## 1. Исходная игровая цепочка без обхода ворот исследования

1. На копии мира Minecraft 1.21.1 NeoForge включить `THAUMCRAFT_SMOKE=1` **до** запуска процесса игры/сервера, сохранив полный настоящий `latest.log`. Установить мод из проверенного feature-коммита, не чужую ветку.
2. Получить `CRYSTALFARMER` реально через систему исследований игрока. Наличие предмета в Creative или одно лишь `/data merge` не является доказательством исследовательского gate. Применить **Basic Caster** к полноценной структуре: центральный пьедестал ровно на `matrix.below(2)`, четыре нужных угловых столба и два дополнительных физически существующих боковых пьедестала в допустимом объёме сканирования `[-8..8] X/Z, [-7..3] Y`.
3. На центральный пьедестал положить **ровно один** `thaumcraft:crystal_essence` с исходным `Aspects:[{key:<аспект>,amount:1}]` без дополнительных NBT-полей. На боковые — **по одному** `minecraft:wheat_seeds` и `thaumcraft:salis_mundus`; их точные `ItemStack` / позиции фиксируются началом ритуала.
4. Поставить настоящие, загруженные, не заблокированные банки эссенции в радиусе реального `InfusionJarSourceBridge`: `10` конкретного аспекта + `10` `vitreus` + `5` `vinculum` **до исходного множителя стоимости**. Действительное число берётся из `PortInfusionLedger.Initial`: по BETA26 каждая стоимость = `(int)(originalAmount * max(0.5f, RecipeCostMult))`. Нельзя выдавать проверку со случайно другой стоимостью за пройденную.
5. Первым реальным кликом активировать матрицу, вторым — начать ритуал через настоящий игровой `BasicCasterItem`; фиксация `TC_SMOKE_INFUSION_CRYSTAL_RESEARCH_GATED_START=YES` обязательна. Никакой команды, непосредственно устанавливающей `crafting:1b`, `PortInfusionLedger` или предмет-результат, в положительном сценарии быть не должно.

## 2. Обязательные наблюдения реальной оплаты

- Сохранить серверные `/data get block x y z` каждого участвующего jar и всех трёх пьедесталов **до и после** ритуала. Действительные `Amount` в банках должны суммарно уменьшиться по аспектам на точное каталожное количество; нельзя подменять проверку только количеством сообщения в логах.
- Для КАЖДОЙ списанной единицы лог содержит `TC_SMOKE_INFUSION_CRYSTAL_JAR_ONE_UNIT_DEBIT_PROVEN=YES`, без `...JAR_DEBIT_INCONSISTENT`. Число успешных списаний равно `sum(Initial)`; их порядок соответствует последовательным физическим действиям сервера.
- Получены `...ESSENTIA_FULLY_PAID`, `...SEEDS_REMOVED`, `...SALIS_REMOVED`, `...REAL_OUTPUT_COMMITTED` от настоящего serverTick; оба боковых слота пусты, и каждый сохраняет receipt с UUID исходного `RitualId`. Центральный содержит один зарегистрированный оригинальный `thaumcraft:crystal_<аспект>` и `PortInfusionOutputRitual` этого UUID.
- После завершения `crafting=false`, нет второго output после следующих 100+ тиков или повторного клика по пустому/неполноценному рецепту. Никакого второго списания и бесплатного кристалла.
- Повторить для **всех семи** BETA26 вариантов: `aer, ignis, aqua, terra, ordo, perditio, vitium` (для `vitium` нестабильность `4`, остальные `0`). Вывод «7/7 PASS» без семи отдельных логов/снимков запрещён.

## 3. Рестарт и аварийные границы — только на копии тестового мира

Сделать снимок/backup мира до каждого эксперимента. Отдельно проверять: (a) обычный сохранённый ритуал с `/save-all flush`, `/stop` и холодной загрузкой; (b) выгрузку/загрузку чанка после частичной оплаты; (c) аварийное завершение процесса на **копии** в момент между записью jar и matrix; (d) между удалением семян и сохранением `ConsumedItems`; (e) между удалением Salis и сохранением `ConsumedItems`; (f) между `RESERVED` и физической публикацией центрального результата.

**Формальные утверждения:** уже выданный результат не выдаётся второй раз; успешное подтверждение STALLED допускается только с тем же `PortInfusionOutputRitual` и обоими side UUID receipts; пропавшее подтверждение НЕ подделывается. Для пунктов (c), (f) код пока намеренно fail-closed; потенциальная потеря ресурса означает **NOT PASS по полной безубыточной приёмке** (даже при отсутствии дюпа). Ни один набор чистых Java unit tests или запущенный без ритуала dedicated server не может закрыть эти проверки.

Отдельные логи со всеми авторитетными `TC_SMOKE_*`, оригинальные снимки block NBT трёх педесталов, jar balances до/после, `PortInfusionLedger` на старте и перед концом, итоговый фактический `ItemStack`, лог восстановления реального мира, исходный commit SHA и ссылки на прошедшую **full NeoForge compile** + настоящую client/server проверку. Только после выполнения каждого критерия можно предъявлять M06.1 на проверку владельцу и предлагать разрешённое слияние PR.
